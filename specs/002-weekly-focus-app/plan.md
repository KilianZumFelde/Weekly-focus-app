## Summary

The Weekly Focus app is a mobile-first personal productivity app (Expo/React Native)
backed by a Hono REST API on Render.com and a Supabase (PostgreSQL) database.
The user organises their life into **themes** (categories), within which they track
**tasks** (one-shot actions with effort/return signals) and **habits** (weekly-recurring
with count targets and streaks). A **goal layer** (1 primary + 2 secondary milestones
with required target dates) anchors all activity. The core daily loop: open → see
This Week → act → capture via voice → Sunday triage ritual.

An **AI Goal Coach** (Claude) helps define and review goals. Voice capture (device STT
+ Claude parsing) creates task/habit drafts that always require explicit user
confirmation. All business logic lives in the API — the mobile app is a pure client.

## Technical Context

**Language/Version**: TypeScript 5.x — strict mode, both mobile and API
**Primary Dependencies**:
- Mobile: Expo SDK (latest stable), Expo Router, @supabase/supabase-js,
  @react-native-voice/voice, expo-notifications, react-native-svg
- API: Hono, Drizzle ORM, @supabase/supabase-js (JWT verification),
  @anthropic-ai/sdk, Zod
- Shared: TypeScript types only (no runtime dependency)
**Storage**: Supabase (PostgreSQL via Drizzle ORM) — cloud, always-online
**Testing**: Jest + integration tests against real PostgreSQL (Supabase test project)
**Target Platform**: iOS + Android (Expo Managed Workflow); API on Render.com (Node 20)
**Project Type**: Mobile app + REST API (monorepo, two packages)
**Performance Goals**:
- Voice capture → draft card visible in < 15 seconds (excluding speaking time)
- Daily check-in (open app + mark one item) in < 60 seconds
- API responses < 500ms p95 for all list endpoints
**Constraints**: Always-online (no offline mode in v1); single user; dark mode default
**Scale/Scope**: 1 user, ~14 screens, 7 entity types, ~30 API endpoints

## Task Conventions

Tasks in `tasks.md` use the following tags in addition to the standard format:

- `[P]` — can run in parallel with other tasks (no file conflicts)
- `[USER]` — requires a manual action from you (creating an account, copying a key, clicking something in a dashboard). Claude will not proceed past a `[USER]` task until you confirm it is done.

`[USER]` tasks look like:
```
- [ ] T012 [USER] Create Supabase project and copy the Database URL + service role key into api/.env
```
Claude will stop at each `[USER]` task, describe exactly what you need to do, and wait for your confirmation before continuing.
